### 2026-10-21 — Merge gate blocks while ANY task is In Progress
**Learning**: `.claude/hooks/pre_bash_block_unsafe_merge.py` refuses every `git merge`/`push` while any KANBAN row is In Progress, and needs a `verify` row containing "pass" for Ready for Review rows. With no review status in Linear (decision: In Progress → Done), move a task to Done only after its Evidence is complete, then merge. Parallel tasks must all reach Done before any of them merges. The command regex `\bgit\s+merge\b` also matches `git merge-base` and `git merge-tree`, so those read-only commands are blocked too: use `git rev-list --count A..B` to check divergence. The hook judges the whole Bash command before any part runs, so a compound `board push done && … && git merge` is refused: push the board status in one call, merge in the next. 2026-10-22: HUN-39/44/49 were verified together, pushed Done, then merged one by one (HUN-44 needed an additive conflict fix in `cli.py` + `tests/leak/harness.py`).

### 2026-10-22 — easy-context facts from the HUN-41 spike
**Learning**: The service needs a root on every call, even `list_indexes` (else "no project root: send the X-Easy-Context-Root header or pass the `root` argument"); easy-personal sends an existing known project's root (≤3 tries on a tool error). `list_indexes` returns `{project_id, root, indexes:[{project_id, root, root_exists, files, slices, last_index_at, indexing, status, ...}]}`, `last_index_at` ISO with ms and offset. In service mode easy-context re-indexes every index every `EASY_CONTEXT_REFRESH_SECONDS` (default 300): all `last_index_at` jump together on that tick — not caused by easy-personal — so `context_index_stale` (index older than latest local commit + 60 s) rarely fires while that timer runs. Index matching is by exact root: a worktree-keyed index is not mapped to its main project. `latest_commit` uses `--remotes` (same owner check as the git part). Tests: `tests/conftest.py` points `EASY_PERSONAL_CONTEXT_URL` at a dead port so no test hits the real service.
**Files**: `src/easy_personal/sources/context.py`, `src/easy_personal/core/store.py`, `src/easy_personal/data/rules.yaml`, `tests/conftest.py`, `tests/fakes/mcp_server.py`

### 2026-11-08 — FR-093 (`/verify DRAFT-report-css`, merged `a2458f0`): shipping a server-side fix, and why the owner's rebuild did not pick it up

### 2026-11-08 — FR-094 (`/verify DRAFT-report-images`, merged `883dc23`): the second half of the report-CSP fix, and two measurement traps

**Files**: `src/easy_personal/surfaces/api.py`, `tests/surfaces/test_api.py`

- **A CSP fix lands one directive at a time.** FR-093 added `style-src` and the report's CSS applied, which made it look done. The images were still blank, for the same reason in a different directive: `img-src` was unset, fell back to `default-src 'self'`, and a `data:` URL is not `'self'`. When a fallback-to-`default-src` defect is found, check every directive the content actually uses before calling it fixed.
- **The tell for a CSP-refused image** is `imgComplete: true, naturalWidth: 0, naturalHeight: 0`. The element finishes its load attempt with no bytes, so a "did it load" check on `complete` alone reports a false pass. Assert the real pixel size.
- **`data:` is safe in `img-src` for a reason worth stating precisely.** A `data:` URL carries its own bytes and makes no request, so it cannot carry a value out. But a `data:image/svg+xml` *could* in principle fetch, and what stops it is the browser's SVG-as-image rule — no external loads, no script — not CSP. Measured in a real `blob:` tab: an SVG with `<image href=remote>`, `xlink:href`, `@import`, `fetch()` and a `<foreignObject>` image rendered 200x100, its script did not run, the security log was empty and a listening TCP sink got 0 connections. Do not carry that reasoning over to `<object>` or `<iframe>`, where a `data:` document is live. `data:` stays refused for `<script src>`, `<iframe src>` and `<object data>` — those are separate directives falling back to `default-src`.
- **Node's `fetch` silently drops a custom `Host` header.** A bad-Host 403 probe written with it comes back 200 and reads as a pass while testing nothing — the same class of false pass as HUN-243's token scan and the `--host` probe aimed at the wrong subcommand. Use `curl -H "Host: evil.example"`, which really sends it.
- **Amend a guard test, never drop its assertion.** `test_csp_keeps_script_and_egress_on_default_src` asserted `img-src` absent. Deleting `img-src` from that loop would have made it green and lost the cover. It now pins `img-src == ["'self'", "data:"]`, which is stricter than "absent": `img-src *`, a host, `blob:`, `https:` and a removed directive all fail it, alongside the existing `font-src`/`connect-src`/`script-src` regressions. Probe a guard test by patching the constant in memory and calling the test directly — nine regressions, all failing, is cheap evidence that the guard guards.
- **Still true and still the thing that bites**: `uv tool install` without `--refresh` reuses a cached wheel and ships stale source, so read the constant back out of the *installed* package, not the repo, before trusting a real run.
